Data::Shared lifecycle/bookkeeping benchmark, 2026-10-17
Perl 5.40.2, x86_64 Linux, HashMap 0.23, one sample per implementation.
Baseline: source immediately before persistence/lifecycle hardening.
Revised: locked lifecycle, validated reopen, shared counts, constant-time LRU,
and root-owned compiled dispatch. Backend files use the same formats.

Command: perl bench/scaling.pl
Defaults: creation sizes 100,1000,3000; working set 128; iterations 2000;
workers 4. A copy of the same script ran against the saved baseline source.

Interpretation:
- Creation of 3000 anonymous children fell from 1.180 s to 0.186 s in these
  samples, about 6.3x faster. Revised cost was about 57-64 wall us per child
  across the sampled sizes. Tests also verify that ordinary creation does
  not enumerate the registry. Anonymous children remain retained in memory.
- With the entire 128-child working set resident, revised median read latency
  was 6.91 us versus 18.12 us in the baseline. LRU updates are now constant
  time. RSS was similar in these samples; the structural improvement does
  not claim to reduce the native segment memory per child.
- With cache_size=1, median reopening latency increased from 34.09 us to
  45.06 us. Reopening now takes the lifecycle lock and validates required
  files. This is a measured correctness/performance tradeoff.
- Four writers completed all 8000 increments without lost updates. Aggregate
  throughput was about 0.33-0.35 million operations/s in both samples. The
  lifecycle changes preserve ordinary leaf-operation concurrency.
- The working-set experiment has warm filesystem pages. Percentiles include
  instrumentation and scheduling and are not production latency guarantees.
- RSS includes the interpreter and allocator history. Creation samples are
  sequential, and the contention samples are brief. Repeat and increase
  DS_BENCH_ITERATIONS for workload-specific conclusions.
- Environment controls: DS_BENCH_SIZES, DS_BENCH_WORKING_SET,
  DS_BENCH_ITERATIONS, and DS_BENCH_WORKERS.
