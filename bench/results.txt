Data::Shared benchmark, 2026-10-17, after review revisions
Historical flat-dispatch sample from the initial review. See scaling-results.txt
for the subsequent lifecycle/bookkeeping comparison.
Single sample on a shared x86_64 Linux host; expect substantial variance.
Perl 5.40.2; HashMap 0.23; Queue::Int 0.10; NDArray 0.06; HyperLogLog 0.06.

Commands:
  DS_BENCH_TIME=2 perl bench/benchmark.pl
  DS_BENCH_TIME=2 perl bench/overhead.pl
  DS_BENCH_TIME=1 perl bench/composite.pl

Rates use measured CPU time. DS_BENCH_TIME is a minimum per case.

Notes:
- The dispatch table above predates the shipped compiled binding, so its
  compiled row no longer describes this code; do not compare against it. The
  ratios below were re-measured against the current code on an idle host
  (loadavg 0.13).
  Flat compiled HashMap gets were 4.7x the string rate in both the comparison
  benchmark and the overhead run. Direct native gets were about 7.3x the
  compiled rate. Results from separate groups are not directly comparable;
  host load and CPU frequency varied substantially.
- Warm composite reads cost about 6 us CPU/op. Cycling through 64 file-backed
  children with cache_size=1 cost about 37 us CPU/op, mostly from reopening
  child handles and mappings. The filesystem page cache was warm; this is
  not a cold-storage latency measurement.
- Anonymous composite cycling preserves all child data after the fix.
  Those children stay open, since anonymous segments cannot be reopened.
- These are single-process CPU throughput measurements. They do not measure
  contention, tail latency, resident memory, or crash durability.
- bench/overhead.pl now divides countit iterations by measured cpu_p,
  rather than the requested minimum duration. Older overhead-table rates
  used that incorrect denominator and should not be used for comparisons.
- A redundant closure was removed from compiled queue push/pop. No general
  before/after speedup is claimed: shared-host variance was too large.
- Prefer native handles and backend batch methods in the innermost loops.
  Profile a real workload before adding an XS facade dispatcher.
